## 5. Gotchas learned this session (also in the skill and memory)

- A killed `next build` empties `.next`; the running server then serves pages whose scripts 500. Build only with
  `task web:rebuild`; never `pkill -f "next build"` from a shell whose command line contains that string.
- `launchctl submit` needs absolute `-o/-e` paths; relative ones exit 78 with nothing logged. `next dev` under launchd
  panics in Turbopack's PostCSS worker even with the shell environment sourced; start it from an interactive shell.
- Never let a wait loop fall through to a build step: a fold was once built while its second export was still running.
- The eyes guard blocks checkpoints after any re-extraction until `scene_confidence --scenes ...` refreshes the index.
- Other projects share this host (Docker CI runners, other Next dev servers, a linter); check memory before builds.
- "teacher" in module names is reserved for the hi-res SAM3 teacher; the reviewer-theme detectors are object hints.
- Hints are never labels; human decisions are never fabricated; the wording is agreement and model estimate, not accuracy.
